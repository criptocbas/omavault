# omavault v0.4 — Hardening Implementation Plan

**Status:** Phases 1–7 are implemented. Phase 1 shipped in v0.3.1 (`b266418`). Phase 2 merged (`265d139`). Phases 3–4 merged (`992a9c5`). Phase 5 merged (`80c714b`). Phase 6 merged (`42a2add`). Phase 7 is on `feat/v0.4-release` (v0.4.0, not tagged, not merged). Round 3 re-audit has not been run.

**Deviations from the plan:**

- Symlinked vault directories are not banned as a class. The vault file and its immediate parent are opened with `O_NOFOLLOW` (a symlink as the last component is rejected) and must be owned by the current user and not group/world-writable. A symlink further up the path is still followed; the ownership and mode checks then apply to the directory that was opened.
- Namespace `ProtectSystem=`, `ProtectKernel*=`, `ProtectControlGroups=`, `ProtectClock=`, `ProtectHostname=`, and `PrivateIPC=` are not in `omarchy/omavaultd.service`. In a user unit they imply `PrivateUsers=yes`, root-owned `fido2-*` appears as uid 65534, and daemon FIDO2 unlock fails.
- `chrono` stays. `RUSTSEC-2026-0543` is accepted in `.cargo/audit.toml` and `deny.toml`. `DateTime<Utc>` is part of the serialized vault, so replacing chrono is a format change.
- MSRV is Rust 1.88 because ratatui 0.30 requires it.
- `deny.toml` allows the licenses actually in the lockfile: MIT, Apache-2.0, Apache-2.0 WITH LLVM-exception, BSD-3-Clause, MPL-2.0 (`option-ext` via `dirs-sys`), Unicode-3.0, Zlib. BSD-2-Clause and ISC are not in the graph. The only ignored advisory is the chrono one.
**Baseline:** `main` @ `a8a5367` (v0.3.0).
**Inputs merged:** 4 independent red-team agents (crypto/format, daemon/IPC, runtime leakage, input/install) + Gemini "Round 2" report.

Every Gemini-only finding referenced below was re-checked against the current code before being included. Items marked *(verified)* were confirmed by reading the code; *(PoC)* were reproduced by an agent against a scratch build.

## Phase 1 — Data-loss hotfix (ship as v0.3.1)

### 1.1 Stop `save_vault_to_disk_checked` clobbering the caller's header — **Critical** (PoC, Gemini C-1)
**Problem:** `src/vault/storage.rs:362` does `*header = disk_hdr;` after the revision check. `rekey` (`cli.rs:1686`), `fido2 remove` both modes (`cli.rs:796`, `:811`) and `fido2 add` v2 (`cli.rs:602`) build a *new* header, which is silently replaced with the old one before sealing. Result: rekey / rotating remove → vault unopenable + backups purged; `--no-rotate` remove → revoked key still works; `fido2 add` → new slot dropped.

**Change:**
1. Split the API so intent is explicit:
   - `save_vault_to_disk_checked(path, key, header: &mut VaultHeader, vault, expected: &str, …)` — verifies the on-disk revision equals `expected`, **never** replaces `header`. Used by every caller that intentionally changes the header and by entry-only saves.
   - Remove the "adopt disk header" behaviour entirely. The daemon already refreshes `session.header` on every `LoadVault`, and after §3.3 (full-header revision) a matching revision *proves* the session header is byte-identical to disk, so adoption is never needed.
2. Seal into a clone and commit only on success (also fixes Gemini **M-8**, verified):
   ```rust
   let mut next = header.clone();
   let blob = seal_vault(master_key, &mut next, &plaintext)?;
   atomic_write_unlocked(path, parent, &blob, create_backup)?;
   *header = next;
   ```
3. Add `verify_on_disk_unlock(path, expected_header, expected_key, passphrase/pw_hash, kf_digest, matched secrets)` used by `rekey`, `fido2 add`, `fido2 remove`:
   - re-read header from disk, assert it equals the header we meant to write (version, flags, KDF params, `kdf_salt`, slot labels + credential IDs);
   - **re-derive** the master key from the on-disk header (v1: Argon2 + HKDF from `pw_hash`; v2: `unwrap_master_key_from_slot` for the slot(s) we hold secrets for) and constant-time compare with the in-memory new key;
   - only then call `purge_encrypted_backups`.
4. Always write a backup (`create_backup = true`) on header-changing saves; purge happens only after step 3 passes.
5. `fido2 add` v1→v2 upgrade (`cli.rs:663`) switches from `save_vault_to_disk` to the checked variant with `expected_rev` (Gemini **M-10**, verified).
6. `init` (`cli.rs:~1025`): perform the "must not exist" check under `FileLockGuard` and use `renameat2(RENAME_NOREPLACE)` (or `link`+`unlink`) so a concurrent init can't be overwritten (Gemini **M-14**).

**Tests (new `tests/header_mutation_tests.rs`)** — each reopens the vault **from scratch** using only passphrase (+ keyfile) + `MockTrackedFido2Key`, never the in-memory key:
- `rekey` → old passphrase fails, new succeeds, entries intact, backups purged only after success.
- `rekey` with simulated failure between save and verify → backups still present, old vault recoverable from `.bak.1`.
- `fido2 add` v2 → new key unlocks; v1→v2 upgrade → both keys unlock.
- `fido2 remove` rotating → removed key fails, remaining keys succeed; `--no-rotate` → removed slot absent from disk header.
- Regression: the existing H-5 concurrency test still passes.

**Docs:** CHANGELOG/README warning: "v0.3.0 `rekey` / `fido2 add|remove` were broken; if you ran them without `--keep-old-backups`, restore from an external backup."

**Acceptance:** all of the above tests green; manual end-to-end with a real YubiKey on a scratch vault (`--vault /tmp/...`).

## Phase 2 — Make locking actually reliable (v0.4.0)

### 2.1 Working pre-sleep / hibernate lock — **High** (PoC ×2, Gemini H-1)
**Problem:** `daemon.rs:280-333` uses `busctl --system monitor` → `BecomeMonitor` is root-only → "Access denied", stderr discarded, thread dies silently. Also matches lowercase `"boolean true"` while busctl prints `BOOLEAN true`. Hypridle fallback points at `$HOME/.local/bin/omavault`, absent on package installs.

**Change:**
1. Replace with a native D-Bus subscriber (per D1) on the **system** bus:
   - `AddMatch` for `type='signal',sender='org.freedesktop.login1',interface='org.freedesktop.login1.Manager',member='PrepareForSleep'` (unprivileged; no monitor rights needed).
   - Take a logind **delay inhibitor**: `Manager.Inhibit("sleep", "omavault", "Wipe vault keys before sleep", "delay")` → hold the returned fd.
   - On `PrepareForSleep(true)`: `lock_inner()` + `clear_clipboard_best_effort()`, **then** close the inhibitor fd (lets suspend proceed). On `PrepareForSleep(false)` (resume): re-acquire a fresh inhibitor.
   - Verify signal sender is the unique name owning `org.freedesktop.login1` (prevents spoofing by another system-bus client).
2. Failure must be loud, not silent: if subscription or inhibitor fails, log to stderr (journald) and expose `presleep_monitor: active|failed(<reason>)` in `DaemonStatus` and `omavault status`.
3. Keep the thread joinable and stop it cleanly on shutdown (Gemini H-1 sub-point).
4. `omarchy/hypridle-hook.conf`: resolve binary like `omavault.lua` does — prefer `/usr/bin/omavault`, fall back to `~/.local/bin` only if `/usr/bin` is absent; PKGBUILD `sed`s the doc copy to `/usr/bin/omavault`.
5. Systemd unit: `RestrictAddressFamilies` already allows `AF_UNIX` (system bus socket) — no change needed; verify under the tightened seccomp from §2.5.
6. TUI standalone mode: same subscriber (shared module `src/sleep.rs`) so a TUI without the daemon also wipes before sleep.

**Tests:** unit-test the signal parsing against real message shapes; integration test against a private `dbus-daemon --session` instance emitting a fake `PrepareForSleep` (gated `#[ignore]` unless `dbus-daemon` exists); manual `systemctl suspend` check that `omavault status` shows `last_lock_reason = pre-sleep` after resume.

**Docs:** SECURITY.md — be explicit that S4 hibernation writes RAM to swap; the inhibitor makes omavault wipe first, but recommend encrypted swap/hibernate image (LUKS).

### 2.2 Bound key lifetime; stop IPC polling from defeating auto-lock — **Medium** (PoC)
**Problem:** `LoadVault`/`SaveVault` refresh `last_activity_boot_secs` (`daemon.rs:773`, `:816`); a same-UID process polling every few seconds keeps the vault unlocked forever (and receives plaintext each time).

**Change:**
1. Add `unlocked_at_boot_secs` to `UnlockedSession` and `max_session_secs` to `DaemonState` (default per D2, CLI `--max-session`, unit file `ExecStart` updated). Watchdog locks with reason `"maximum session lifetime reached"` regardless of activity.
2. Expose `session_remaining_secs` in `DaemonStatus`; TUI shows it.
3. SECURITY.md: correct the "Same-UID … DEFENDED" claim — a same-UID process **can** read an unlocked daemon's vault via the socket (inherent to any agent model); what is defended is ptrace/core-dump/cross-UID access, and exposure is time-bounded.

**Tests:** daemon test with `max_session_secs = 3`, poll `load_vault` every 1s → locked after ≤4s.

### 2.3 Emergency lock can no longer be starved — **Medium** (PoC, Gemini M-4)
**Problem:** the "8 reserved control slots" (`daemon.rs:34`) don't exist; `MAX_TOTAL_WORKERS` is enforced before the request type is known (`daemon.rs:519`). 18 idle connections → `omavault lock` gets "daemon busy". Busy-reject also does a blocking 250 ms write on the accept thread.

**Change (defence in depth — signals can't be starved by socket floods):**
1. **Signal fallback in `omavault lock`:** if the socket request fails or returns busy, send `SIGUSR1` to the daemon. Daemon writes its PID into `daemon.lock` (already flocked); client verifies `/proc/<pid>` uid == euid and `/proc/<pid>/exe` resolves to the same binary path as `current_exe()` (or `/usr/bin/omavault`) before signalling. Exit non-zero with a clear message only if both paths fail.
2. **Instant SIGUSR1 handling:** replace the 1-second sleep poll for signals with a `signal_hook::iterator::Signals` thread (or self-pipe) so SIGUSR1 locks immediately (Gemini **L-2**).
3. **Real control reservation:** per-connection first-frame deadline drops from 10 s to **1 s** (control frames are tiny; heavy requests send their frame immediately too). Unclassified connections are capped at `MAX_TOTAL_WORKERS - RESERVED_CONTROL (8)`; the last 8 slots only accept a connection if its first frame parses as `Lock`/`Status`/`Shutdown` within 250 ms.
4. Busy-reject: set the socket non-blocking and best-effort `send(MSG_DONTWAIT)` the error, never block the accept loop.
5. `write_frame` gets an overall monotonic deadline (Gemini M-4 sub-point) so a slow reader can't pin a plaintext response across a lock.
6. `read_frame`: `try_reserve_exact` + incremental growth in fixed chunks instead of `Vec::with_capacity(total_len)` up front.
7. Client `connect_unix_with_timeout` (`hardening.rs:715`): retry `connect()` on `EAGAIN` with brief backoff and retry `poll()` on `EINTR` within the deadline (Gemini **L-3**).

**Tests:** spawn 32 silent connections, assert `omavault lock` still locks (via either path) within 1 s; assert SIGUSR1 lock latency < 200 ms.

### 2.4 Lock hotkey also locks a standalone TUI — **Low–Medium**
**Problem:** with no daemon, `omavault lock` (`cli.rs:912`) only clears the clipboard; a standalone TUI keeps keys and plaintext on screen.

**Change:**
1. TUI registers `SIGUSR1` → `lock_vault("emergency lock")`.
2. TUI writes a registry file `$XDG_RUNTIME_DIR/omavault/tui.<pid>` (0600, removed by `TuiGuard`).
3. `omavault lock` always (daemon or not) iterates the registry, verifies each PID as in §2.3.1, sends `SIGUSR1`, removes stale entries. Replaces the locale-dependent `"Connection refused"` string matching with a typed `VaultError::DaemonUnavailable` (Gemini **M-12**, verified).

### 2.5 Fix and tighten the systemd unit — **Medium** (verified with `systemd-analyze verify`, Gemini M-3)
**Problem:** `omavaultd.service:23` puts `~@…` tokens mid-line → systemd logs "System call ~@privileged is not known, ignoring" ×10; deny list is a no-op.

**Change:**
```ini
SystemCallFilter=@system-service
SystemCallFilter=~@privileged @mount @module @raw-io @reboot @swap @clock @cpu-emulation @debug @obsolete
```
Then try, one at a time, and **keep only what works with a real YubiKey + Hyprland lock detection**:
`PrivateTmp=yes`, `ProtectKernelTunables=yes`, `ProtectKernelModules=yes`, `ProtectKernelLogs=yes`, `ProtectControlGroups=yes`, `ProtectClock=yes`, `IPAddressDeny=any`, `ProtectSystem=strict` + `ReadWritePaths=%h/.local/share/omavault %t/omavault`. (Note: in user units several `Protect*` options imply `PrivateUsers=` — must confirm `/dev/hidraw*` access survives.) `CapabilityBoundingSet=` is a no-op for user units; skip. `ProtectProc=invisible` is incompatible with the `/proc` locker scan; document why.

**Tests:** CI step `systemd-analyze verify omarchy/omavaultd.service` must emit **zero** warnings; record `systemd-analyze security --user --offline` score before/after in the PR.

### 2.6 Daemon race fixes (Gemini, verified)
- **M-1:** `LoadVault` (`daemon.rs:751`) — capture `start_epoch`, re-check `!shutdown_requested && lock_epoch == start_epoch` after acquiring `io_lock` and again before returning plaintext; drop the decrypted vault if the check fails.
- **M-2:** `Unlock` commit path calls `is_screen_locker_active()` while holding `state.lock()` (`daemon.rs:~741`) — compute it *before* taking the mutex; give the Hyprland probe a single overall deadline.
- **L-1:** increment `lock_epoch` when committing a new session; `SaveVault` re-verifies `session.vault_path == canonical` after `io_lock`.
- **M-15:** `SaveVault` returns `DaemonResponse::Saved { revision }`; TUI stops doing a full plaintext `load_vault` round-trip after each save (`tui/mod.rs:477-484`).

### 2.7 TUI unlock-cancel race — **High** in Gemini, verified (H-4)
**Problem:** cancelling during `Mode::Unlocking` calls `client.lock()`; if that lands before the worker's `Unlock` reads `start_epoch`, the daemon unlocks after the user cancelled. Standalone worker keeps the passphrase and FIDO2 child alive after cancel.

**Change:** `Arc<AtomicBool>` cancel flag shared with the worker. Worker: after `client.unlock()` returns Ok, if cancelled **or** `tx.send()` fails (receiver dropped) → `client.lock()`. Standalone: check flag between KDF and FIDO2, wire it into `fido2::wait_with_timeout` so `fido2-assert` is killed immediately (process-group kill, Gemini **L-4**). RAII guard on `Mode::Unlocking` sets the flag on drop/unwind.

## Phase 3 — Integrity & output safety (v0.4.0)

### 3.1 Terminal-escape injection on CLI output — **Medium** (PoC)
**Problem:** `get --reveal` prints password/notes raw (`cli.rs:1283-1289`); `tty_safe` (`cli.rs:445`) disables sanitizing whenever stdout is piped, so `omavault list | less -R` / `| grep` forwards OSC-52 / OSC-8 / title escapes to the terminal. Gemini's "sanitizer clean" verdict only covered the TUI.

**Change:**
1. Display fields (name, username, url, tags, labels, issuer, error strings) are **always** sanitized with `sanitize_single_line`, TTY or not. New global `--raw` flag opts out for scripting.
2. `get --reveal` on a TTY: notes via `sanitize_multiline`; a password containing C0/C1/DEL/BiDi chars is refused on a TTY ("contains control characters; use `--copy`"). When piped, secrets are emitted byte-exact (needed for `| wl-copy`, etc.).
3. Input side: hidden prompts (`--notes-prompt`, password prompt, TUI fields) reject or strip C0/C1 except `\n`/`\t` in notes, so a clipboard-hijacked paste can't plant escapes in the first place.
4. Apply `stderr_tty_safe` to remaining `eprintln!` sites that interpolate entry/slot data (Gemini L-12).

**Tests:** golden tests feeding `\x1b]52;c;…\x07`, `\x1b]8;;…`, `‮`, `\x9b` through every print path, TTY and non-TTY (use a pty in tests).

### 3.2 Rollback protection — **Medium** (PoC)
**Problem:** any older authentic vault (old copy, `.bak.N`, sync conflict) is accepted silently — including a pre-revocation copy after `fido2 remove`.

**Change (no binary format change; lives inside the AEAD payload):**
1. Add to `Vault` (serde `default`, so v0.3 vaults still load): `vault_id: Uuid` (generated on first v0.4 save if absent), `generation: u64` (incremented on every save).
2. Local state `~/.local/state/omavault/seen/<vault_id>` (0600, dir 0700, `O_NOFOLLOW`): `{ max_generation, kdf_salt_fingerprint }`, updated atomically after every successful load/save.
3. On unlock: if `generation < max_generation` → refuse per D4 with a message showing both numbers and `--allow-rollback` to override (which then rewrites the seen state). If `kdf_salt` fingerprint differs at the same/greater generation → informational (legitimate rekey elsewhere).
4. Document the limits: protects against file swap / restore, not against an attacker who can also rewrite `~/.local/state`.

**Tests:** save ×3, restore generation-1 blob → refused; `--allow-rollback` → accepted; v0.3 vault (no fields) → loads with warning, gets an ID.

### 3.3 Full-header revision token (stops tamper "laundering") — **Low–Medium** (PoC)
**Problem:** `header_revision()` (`crypto/mod.rs:454`) is just `hex(save_salt)`. An attacker who edits the header but keeps `save_salt` passes the check, and (pre-Phase-1) the next save re-authenticated the forged header.

**Change:** `header_revision = hex(BLAKE3("omavault-header-rev-v1" || header.to_bytes()))`. Revision strings are opaque to clients, so the IPC contract is unchanged. Combined with Phase 1 (no adoption), any header edit now causes "modified concurrently on disk" instead of being silently accepted.

**Tests:** edit a slot label on disk keeping `save_salt` → next save fails with revision mismatch.

### 3.4 Filesystem trust checks on the read path — **Low** (PoC)
**Problem:** `read_bounded_regular_file` / `read_header_from_disk` (`storage.rs:288,323`) never check the directory or file owner/mode; a symlinked or 0777 vault dir is followed. `ensure_private_dir` (`storage.rs:105`) silently `chmod`s "dedicated" dirs back to 0700 instead of refusing. Daemon `canonicalize` follows symlinks.

**Change:**
1. New `verify_vault_location(path)` used by **every** read and write: open parent with `O_DIRECTORY|O_NOFOLLOW`, require `uid == euid` and `mode & 0o022 == 0`; open the vault via `openat(dirfd, name, O_NOFOLLOW)`; require file `uid == euid`, `mode & 0o022 == 0`, `nlink == 1`.
2. `ensure_private_dir`: chmod only directories **we just created**; an existing dir with bad perms → hard error with a fix-it hint.
3. Daemon: compare `canonicalize(path)` with the absolutized path; refuse if they differ (symlinked component).
4. Lock file: reject `nlink > 1` before `fchmod` (`storage.rs:136`).
5. `purge_encrypted_backups` also removes `.<name>.tmp.*` and `.<name>.bak.*.tmp.*` leftovers and `fsync`s the parent dir (Gemini L-12).
6. `hash_keyfile`: require keyfile `uid == euid`, retry on `EINTR` (Gemini **L-7**).

### 3.5 Smaller output/UX security fixes
- `omavault generate` default per D3.
- `fido2 list` (`cli.rs:486`): header is unauthenticated at that point → print a "(unverified — unlock to confirm)" note, sanitize labels; `validate_slot_label` additionally rejects BiDi controls and zero-width chars (U+200B–U+200F, U+202A–U+202E, U+2066–U+2069, U+FEFF).
- `--totp-file`: require 0600 + owner + bounded size (Gemini L-9).

### 3.6 TUI correctness bugs (Gemini, verified)
- **H-2:** `GenModalState` defaults `words: 8` (`tui/mod.rs:213`) while the generator requires 10–24 → blank passphrase shown as "STRONG". Default 12, bounds 10..=24, show generator errors instead of `unwrap_or_else(String::new)`, unit test both modes.
- **M-11:** `current_mut()` sets `totp_modified = true` on *any* access to field 5 (`tui/mod.rs:183`), silently downgrading custom TOTP params. Compare final value with original at commit time instead.
- **M-13:** render multi-line notes as one `Line` per line.

## Phase 4 — Memory hygiene (v0.4.0)

### 4.1 Zeroizing global allocator — fixes a whole finding class (D5)
**Findings covered:** serde_json escape scratch buffers leaking passwords/notes/master passphrase (PoC ×2); TUI `sanitize_*` copies per frame (PoC); `get --reveal` clone; stdout `LineWriter` buffer; Gemini **M-5** (FIDO2 stdout realloc), **M-6** (TOTP base32 realloc), **L-9** (prompt buffers).

**Change:** `src/alloc.rs`:
```rust
pub struct ZeroizingAlloc;
unsafe impl GlobalAlloc for ZeroizingAlloc {
    unsafe fn alloc(&self, l: Layout) -> *mut u8 { System.alloc(l) }
    unsafe fn alloc_zeroed(&self, l: Layout) -> *mut u8 { System.alloc_zeroed(l) }
    unsafe fn dealloc(&self, p: *mut u8, l: Layout) {
        zeroize::Zeroize::zeroize(core::slice::from_raw_parts_mut(p, l.size()));
        System.dealloc(p, l)
    }
    // realloc: default impl = alloc + copy + self.dealloc → old block is wiped.
}
#[global_allocator] static A: ZeroizingAlloc = ZeroizingAlloc;
```
Still fix the obvious hot spots explicitly (pre-sized `Zeroizing` buffers in `fido2.rs:654`, `totp.rs normalize_base32`, `cli.rs:1285` no clone) so correctness doesn't depend solely on the allocator.

**Tests:** port the agents' heap-canary harness into `tests/heap_residue.rs` (counting allocator in test, assert zero blocks containing a canary after drop for: escaped notes, escaped passphrase unlock request, TUI sanitize).

### 4.2 Swap exposure of decrypted vault
**Problem:** only the 32-byte `LockedKey` is mlocked; decrypted entries in TUI/CLI heap are swappable. `mlockall(MCL_FUTURE)` is **not** viable: default `RLIMIT_MEMLOCK` is 8 MiB and Argon2 needs 128 MiB+ → allocation failures.

**Change:** (1) daemon never retains plaintext between requests (already true — keep it, add a test). (2) At startup, inspect `/proc/swaps`; if any non-zram, non-dm-crypt swap is active, show a warning in `omavault status` / TUI header. (3) SECURITY.md: replace "prevent secret material from reaching swap" with an accurate statement (key is mlocked; decrypted entries rely on encrypted swap/zram).

### 4.3 Stack-resident HKDF/HMAC state — Low/Info
`hkdf`/`hmac` 0.12 don't zeroize. Track upgrade to 0.13; meanwhile wrap derivations in `#[inline(never)]` helpers followed by a small volatile stack scrub. Document as residual risk.

## Phase 5 — Clipboard races (v0.4.0, Gemini, verified)

- **H-3:** `copy_secret` signals the old helper, spawns the new one, and only then writes `clip.state` (`clipboard.rs:211-266`); the old helper's SIGTERM path sees itself as current and calls global `copy::clear`, wiping the new secret. **Fix:** take `flock(LOCK_EX)` on `clip.lock`; write the new generation to `clip.state` *before* signalling the old helper; a superseded helper never calls global `clear()` — it just exits (dropping its Wayland source withdraws only its own selection).
- **M-9:** all `clip.state` read/write/unlink under the same `clip.lock`.
- **L-11:** register SIGTERM/SIGINT handlers before printing `OK`.

**Tests:** stress test: 50 rapid `copy_secret` calls with short timeouts; assert the last secret is never cleared before its own timeout (mock clipboard backend behind a trait).

## Phase 6 — FIDO2 robustness (v0.4.0, Gemini, verified)

- **M-7:** `assert_matching_slot` (`fido2.rs:509-521`) `break`s to the next device on *any* non-"no matching credential" error, so a `require_uv` slot probed first on a PIN-less backup key locks the user out. Probe `require_uv == false` slots first per device; `continue` on per-slot PIN/UV errors; `break` only on transport/timeout/disconnect.
- **L-4:** spawn `fido2-*` in their own process group, verify `getppid()` after `PR_SET_PDEATHSIG`, RAII child guard that `kill(-pgid, SIGKILL)` + reaps.
- **L-5:** v1 single-key path uses `assert_on_any_device`.
- **L-6:** biometric-only tokens: try `-t uv=true`, fall back to `-t pin=true`; UV flag verification remains the gate.
- **L-8:** `resolve_master_key` uses `.get(slot_idx)`; `VaultHeader::to_bytes()` validates KDF upper bounds.

## Phase 7 — Packaging, supply chain, docs

1. **Binary path:** `hypr-omavault.conf` and `hypridle-hook.conf` stop hard-coding `$HOME/.local/bin`; PKGBUILD `sed`s installed doc copies to `/usr/bin/omavault`; `install.sh` warns if a stale `~/.config/systemd/user/omavaultd.service` would shadow the packaged unit. Add Alacritty `-o selection.save_to_clipboard=false` + OSC-52 disable; update Ghostty flags (Gemini L-10).
2. **PKGBUILD:** `source=("git+…#tag=v$pkgver?signed")` with `validpgpkeys`, `prepare() { cargo fetch --locked; }`, build/check with `--frozen`; add `dbus` to `depends` (D1).
3. **Dependencies:** upgrade `ratatui` 0.29 → 0.30 (pulls patched `lru`, drops `paste`). MSRV is Rust 1.88 because ratatui 0.30 requires it. `chrono` stays for v0.4.0 (`RUSTSEC-2026-0543` accepted: `DateTime<Utc>` is part of the serialized vault, and replacing it needs a compatibility test). Add `cargo audit` + `cargo deny` (licenses, advisories, no git deps) to CI.
4. **CI (`.github/workflows/ci.yml`, new):** `cargo fmt --check`, `clippy -D warnings`, `cargo test --locked`, `cargo audit`, `systemd-analyze verify` on the unit, short `cargo fuzz` smoke runs (header parser, otpauth, vault JSON) reusing the agents' harnesses.
5. **SECURITY.md rewrite of overclaims:** same-UID IPC access, swap/heap statement, pre-sleep mechanism, PKGBUILD shadowing claim, add rollback-protection + its limits, add hibernation guidance. Add a "Known limitations" section.
6. Bump to **v0.4.0**, CHANGELOG listing every finding ID → fix.
